# Lab 4 AI Use & Reflection

A living document recording the key prompts used during Sprint 4 (Actions Taken, Ticket Workflow, Role Dashboards, and Final Regression). This document demonstrates how AI was utilized not just for code generation, but as a sparring partner for specification consistency, concurrency architecture, deep-stack debugging, and strict contract enforcement.

## 1. AI Assistant Details

- **Primary Tool:** Google Antigravity IDE (Gemini)
- **Role:** Specification Agent, Backend Concurrency Architect, and Full-Stack QA Debugger.
- **Workflow:** Iterative Specification-Driven Development (Spec-DD) and Test-Driven Development (TDD). Rather than blind code generation, the AI was required to draft formal specifications (`specification.md`, `api-spec.md`, `ui-spec.md`, `tests.md`) and submit execution plans for human critique before writing code, then debug real stack traces and peer-review findings across the full stack (Prisma → Express → React → Playwright).

## 3. Workflow Observation

Rather than treating the AI purely as a code generator, I utilized it across Sprint 4 as a **Specification Agent**, **Architecture Sparring Partner**, and **Full-Stack Debugger**.

When acting as a **Specification and Planning Agent**, the AI excelled at structuring comprehensive API schemas and test matrices, but it required strict human oversight to prevent subtle architectural drift across files—such as inconsistent route paths, dead controls like `UNSET` priority, or filter parameters (`active=true` + `status=...`) overwriting each other. Requiring a reviewable plan and cross-checking contracts before implementation caught these discrepancies early.

When shifting to a **Coding and QA Agent**, the AI was most effective when challenged on its implementation assumptions ("Why are we rendering two separate tables for desktop and mobile?", "Why is the modal backdrop cut off in full-page screenshots?") or when fed exact test failure traces. Combining Specification-Driven Development (Spec-DD) with rigorous human review ensured that the final system achieved 100% bidirectional traceability and zero regressions across all Lab 1–4 features.
