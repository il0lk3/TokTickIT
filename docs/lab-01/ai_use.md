# Lab 1 — AI Use and Reflection  

**รายละเอียดเครื่องมือ AI ที่ใช้งาน:**
- **AI Coding Agent:** Antigravity (Google Deepmind)
- **โมเดล LLM:** Gemini 2.0 Flash พร้อมระดับ Thinking

## ตารางสรุปคำสั่งสำคัญ (Selected Key Prompts)

| Prompt Name & Actual Prompt Text | My Reflection (ข้อคิดเห็น/บทเรียน) |
|----------------------------------|------------------------------------|
| **1. การจัดการ Git เบื้องต้น**<br>*"วิธีอัพ issue1 ขึ้น github"* | ตอนแรกยังไม่ค่อยมั่นใจเรื่องคำสั่ง Git เวลาแตก Branch พอถาม AI ทำให้ได้เรียนรู้กระบวนการ Commit และ Push ที่ถูกต้อง บทเรียนคือเราควรเข้าใจลำดับการทำงานของ Git ก่อนนำไปใช้จริง ไม่ใช่แค่ก๊อปปี้คำสั่งมาวางเพียงอย่างเดียว |
| **2. การแก้ไขโค้ดตาม Peer Review**<br>*"issue 2 มีเพื่อนมา review ให้แก้... ช่วยแก้หน่อย"* | เมื่อได้รับ Feedback จากเพื่อน การนำข้อความนั้นมาปรึกษา AI ทำให้เราได้เรียนรู้วิธีการเขียนเงื่อนไขรองรับเคสที่เราคาดไม่ถึง (Edge cases) อย่างกรณี `online: false` เป็นการเปิดมุมมองใหม่ในการดักจับ Error ที่ดีมาก |
| **3. การจัดการปัญหาบน GitHub PR**<br>*"ลบ approve อันเก่าได้ปะ"* | สะท้อนให้เห็นว่า AI ไม่ได้เก่งแค่เรื่องเขียนโค้ด แต่ยังช่วยแนะนำการใช้งานเครื่องมืออย่าง GitHub ได้ด้วย การถามคำถามนี้ทำให้เราเข้าใจ Workflow ของระบบ Pull Request และสิทธิ์ในการจัดการ Review มากขึ้น |
| **4. การตั้งค่า Database (Docker)**<br>*"สร้างเป็น docker compose ให้หน่อยได้ปะ (Port 5435)"* | การตั้งค่า Database มักเป็นเรื่องยุ่งยาก แต่ AI ช่วยสร้าง `docker-compose.yml` ให้พร้อมใช้งาน สิ่งที่ตกผลึกคือเราควรระบุเงื่อนไขให้ชัดเจน (เช่น ขอ Port 5435) ยิ่งเราให้ Context ละเอียด ผลลัพธ์ก็จะตรงกับความต้องการของเราตั้งแต่ครั้งแรก |
| **5. การทำ Clean Code**<br>*"เพื่อนมีแนะนำมานิดหน่อย ทำตามดีไหม (Issue 3)"* | บทเรียนนี้มีค่ามาก เพราะ AI ช่วยคอนเฟิร์มว่าคำแนะนำของเพื่อนเป็น Best Practice ที่ควรทำ (เช่น การลบ TODO/console.log ออก) ทำให้เราตระหนักได้ว่าการเขียนโค้ดที่ทำงานได้ไม่ใช่จุดสิ้นสุด แต่ความสะอาดของโค้ด (Clean Code) ก็สำคัญไม่แพ้กัน |
| **6. การรับมือกับ Feedback ที่คลาดเคลื่อน**<br>*"มี review issue4 มาอีกกกกกก"* | นี่คือจุดที่สอนให้เรารู้จัก 'เอ๊ะ' ก่อนลงมือทำ บางครั้ง Feedback จากเพื่อนอาจจะมาจาก Commit เก่า AI ช่วยให้เราใจเย็นลงและตรวจสอบสถานะโค้ดปัจจุบันก่อน ทำให้เราไม่เผลอแก้โค้ดซ้ำซ้อนหรือพังโดยไม่จำเป็น |
| **7. การใช้ AI ช่วยจัดการงานเอกสาร**<br>*"หลักฐานการ Peer Review ของไฟล์ docs/lab-01/reviewer.md น่าจะต้องมีข้อมูลตามนี้นะ"* | การทำเอกสารมักใช้เวลามาก การป้อนข้อมูลดิบให้ AI ช่วยจัดโครงสร้างให้อ่านง่าย ทำให้งานเป็นระเบียบและรวดเร็วขึ้น สิ่งที่ได้เรียนรู้คือ AI เป็นผู้ช่วยลดภาระงานซ้ำซากได้ดีเยี่ยม แต่เรายังต้องเป็นคนตรวจทานความถูกต้องในท้ายที่สุดเสมอ |
| **8. การเขียน Test ให้ลึกซึ้งยิ่งขึ้น**<br>*"รีวิวจากเพื่อน - ... เพิ่ม test กรณีที่ API error แล้วก็เช็ก response ว่ามี id กับ name ครบไหม"* | การใช้ AI ช่วยแก้โค้ดจาก Feedback นี้ทำให้ได้เรียนรู้วิธีการเขียน Test ในระดับที่ลึกขึ้น (เช่น เช็คระดับ Property) และเห็นว่า Test ที่ดีไม่ใช่แค่เช็คว่าทำงานสำเร็จ (Success) แต่ต้องเช็คครอบคลุมถึงกรณีที่พัง (Error 404) ด้วย |
